# claude-code-project-workflow

Claude Code でプロジェクトを進めるためのスキル集です。プロジェクトの始め方、定期点検、作業の種類ごとのルールを、決まった形で揃えます。

## できること

- **新しいフォルダを、決まった構成のプロジェクトとして立ち上げる**(`/00-kickoff`)。やりたいことを聞き取り、`CLAUDE.md`、`TODO.md`、目的・決定事項・確認事項の記録ファイルを、中身を埋めた状態で作ります。git の初期化と、コミットの作者欄の確認も行います
- **プロジェクトが構成から外れていないかを点検する**(`/00-checkup`)。散らかったファイル、更新されていない記録、雛形のままのファイルを見つけ、承認したものだけを直します。`all` を付けると、複数のプロジェクトを並べて比較します
- **全プロジェクトの、自分が動く・待つタスクを 1 枚のボードで見る**(`/00-board`)。各プロジェクトの `タスクボード.md` を集めて、ブラウザで開いたままにできる HTML にします。自動で作り直すための hook の入れ方は、`skills/00-board/SKILL.md` にあります
- **作業の種類に応じたルールを、Claude が自分で読み込む**(`99-rules-*`)。文書、資料、コードとインフラ、調査の 4 種類です
- **上の 3 つをつなぐ共通ルールの見本を使う**(`examples/global-CLAUDE.md`)

| スキル | 呼び出し | 役割 |
|---|---|---|
| `00-kickoff` | `/00-kickoff` と入力 | プロジェクトを始める。標準構成の正本(`structure.md`)と雛形を持つ |
| `00-checkup` | `/00-checkup` と入力 | 標準構成との差を点検し、直す |
| `00-board` | `/00-board` と入力 | タスクボードを作り直して開く。`タスクボード.md` の書き方(`format.md`)を持つ |
| `99-rules-documents` | 自動 | 設計書、手順書、報告書などを書くときのルール |
| `99-rules-materials` | 自動 | スライド、表、HTML、図などを作るときのルール |
| `99-rules-code` | 自動 | IaC、スクリプト、コマンド実行のときのルール |
| `99-rules-research` | 自動 | 調べて答えるときのルール |

## 使い方

### 1. 入れる

リポジトリを手元に置き、スキルのフォルダからリンクを張ります。

```sh
git clone https://github.com/suraud/claude-code-project-workflow.git ~/src/claude-code-project-workflow
cd ~/src/claude-code-project-workflow
mkdir -p ~/.claude/skills
for d in skills/*/; do ln -s "$PWD/$d" ~/.claude/skills/; done
```

同じ名前のスキルがすでにあると、リンクは作られません。先に名前が重ならないかを確かめてください。

### 2. 共通ルールを置く

`examples/global-CLAUDE.md` を読み、自分の進め方に合わせて書き換えてから、`~/.claude/CLAUDE.md` に置きます。すでに `~/.claude/CLAUDE.md` がある場合は、必要な部分だけを足してください。共通ルールがなくてもスキルは動きますが、点検日の案内やルールの育て方が働かなくなります。

### 3. 始める

新しい空のフォルダで Claude Code を開き、`/00-kickoff` と入力します。やりたいことを話すと、構成の案が示され、承認すると作られます。

## 自分用に直して使う

このスキル集は、作者が実際の作業で使っている決まりを、そのまま見本として公開しています。「理由は太字の結論 1 文 + 根拠 2〜3 文で書く」「作業フォルダの外を読み書きしない」のように、好みが分かれる決まりも含みます。合わないものは、自分の作業に合わせて書き換えてください。

- 標準構成を変えるときは、`skills/00-kickoff/structure.md` と `skills/00-kickoff/templates/` を一緒に直します。`/00-checkup` も、承認を得てここを直します
- 直した内容は、clone したリポジトリの変更として残ります。上流の更新を `git pull` で取り込むとき、同じ箇所を直していると衝突することがあります

## 前提

- Claude Code のスキル(`~/.claude/skills/`)が使えること
- 日本語で作業すること。フォルダ名とファイル名(`docs/00_前提/`、`決定事項.md` など)も日本語です
- 次の skill が導入されていれば、資料や文書を作るときに使います。なくても動きます:`pptx`、`xlsx`、`docx`、`dataviz`、`doc-coauthoring`
