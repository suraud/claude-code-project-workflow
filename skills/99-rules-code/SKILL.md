# コードとインフラ作業のルール

IaC、スクリプト、コマンド実行、手順の検証のあいだ、次のルールに従う。プロジェクトに独自のルールがあれば、そちらを優先する。

## 確認のしかた

- 環境ごとの構成は、対象の環境の実物(そのブランチ、そのアカウント)で確かめる。既定のブランチや 1 つの環境で見た結果を、他の環境に当てはめない。一覧の先頭に出たものを正解と決めつけない
- 手順やスクリプトの検証は、それを使う人の環境を基準にする。自分の端末に残っている認証情報や鍵で動いたことを、確認の根拠にしない
- 認証できること、権限があること、読めること、書けることは別々に確かめる。1 つが通っても他は保証されない

## 書き方

- スクリプトは、何度実行しても同じ結果になるように書く。途中で失敗しても、やり直せるようにするため
- zsh では、複数の語からなるフラグを 1 つの変数に入れて渡さない。分割されずに 1 つの引数として渡り、失敗する。フラグは直接書く
- 秘密情報(パスワード、トークン、鍵)をファイルに書かない。出力にも出さない

## 実行のしかた

- 環境を変える操作(apply、削除、push、本番への接続)は、実行前に対象と影響を示して確認を取る
- 実行結果は、成功も失敗もそのまま報告する。失敗した場合は出力を添える。確かめていないことを「動く」と書かない
