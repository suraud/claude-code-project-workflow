# タスクボード.md の書き方

`docs/00_前提/タスクボード.md` は、利用者が動くこと・待つことの一覧。タスクボード(`/00-board`)に載る内容の正本になる。利用者が動く・待つことが最初に出てきた時点で作る。雛形は `~/.claude/skills/00-board/templates/タスクボード.md`。

## ほかのファイルとの分け方

| ファイル | 書くこと |
|---|---|
| `TODO.md` | Claude が進める作業と、現在地 |
| `docs/00_前提/確認事項.md` | 未決事項の中身(質問、回答、経緯) |
| `docs/00_前提/タスクボード.md` | 利用者が動く・待つことの一覧(だれの番か、いつまでに、次に何を) |

同じことを 2 か所に書かない。カードには中身(回答、経緯)を書かず、出典と、なぜ必要かだけを書く。

## 形

```markdown
# タスクボード

次の番号: 5

## 相手の回答待ち

- #1 ログ欠落の件:担当者の回答
  - 相手: ○○社 ○○さん
  - 場所: 課題管理 ABC-123
  - 期限: 2026-01-15
  - 最後の動き: 2026-01-10 相談を投稿(未読)
  - 次にやること: 回答を受けて対策を決める。期限を過ぎたら催促する

## 自分がやる・決める

- #2 報告するかどうかを決める
  - 場所: Wiki「運用ルール」
  - 期限: 未設定
  - メモ: 報告先によって、手順書の書き方が変わるため

## Claude からの質問

- #4 定例の開催日は、いまはいつか
  - 場所: Wiki「定例の進め方」
  - メモ: 3 通りの記述がある。手順書に書く日を決めるため

## 手が空いたら

- #3 構成の見直し
```

- 節は 4 つ。見出しの語(「回答待ち」「やる」「質問」「手が空いたら」)で見分けるので、変えない
- 「Claude からの質問」には、Claude が作業を進めるために、利用者に答えてほしいことを書く。利用者が自分で動くこと(やる・決める)とは分ける
- カードは、行頭の `- #番号 件名`。項目は、字下げした `- 名前: 値`。使える名前は、相手、場所、期限、最後の動き、次にやること、メモ。それ以外の字下げした行は、補足としてそのまま載る
- 日付は `YYYY-MM-DD` で書く。ボードが、期限までの日数と、最後の動きからの日数を計算する

## カードの中身

- カードは 1 つの論点にする。複数の質問や用件を 1 枚にまとめない。まとめると、一部に答えたところで残りが雑に片づく
- カードには、利用者が何の話か思い出せる材料を書く。「場所」に出典(ページ名、課題キーなど)を必ず書き、「メモ」に、なぜ必要かを 1 行で書く。利用者は、Claude が調べた経緯を覚えていない。確認事項の番号だけを指さない
- 利用者が「知らない」「自分は確認しない」と答えたことは、利用者のカードにしない。Claude が調べるなら `TODO.md` に移す

## 番号

- プロジェクトごとの通し番号を振る。利用者が「3 番を進めたい」と言えば、どのカードかが分かるようにするため
- 新しいカードには、ファイルの先頭の「次の番号」を使い、「次の番号」を 1 つ進める。片づいたカードの番号を使い回さない
- カードを別の節に移しても、番号は変えない
- 声や文で番号を言うときは、「カードの 9 番」と言う。`確認事項.md` の項目は、番号でなく件名で言う(番号が別に振られていて、混ざるため)

## 期限

- 「相手の回答待ち」のカードには、必ず期限を書く。相手に伝えた期限がなければ、催促する日を利用者と決めて書く。期限のないカードは、止まっていても気づけない
- 期限が来たカードは、ボードの「いま対応する」に自動で移る

## 更新する時機

そのプロジェクトのセッションが、自分の判断で書き換える。利用者に確認を取らない。書き換えたら、何をしたかを一言で報告する(例:「3 番を、相手の番に移しました」)。

| 起きたこと | すること |
|---|---|
| 相手に質問・依頼・相談を送った | 「相手の回答待ち」にカードを足す。すでに「自分がやる・決める」にあれば、そこから移す |
| 相手に催促した、相手が読んだ | 「最後の動き」と「期限」を直す |
| 相手から返事が来た | 利用者が次に動くなら「自分がやる・決める」に移し、「次にやること」を直す。それで終わりなら消す |
| 利用者がやること・決めることが出てきた | 「自分がやる・決める」に足す。急がないものは「手が空いたら」に足す |
| 利用者に答えてほしい質問が出てきた | 「Claude からの質問」に足す。中身(回答、経緯)は `確認事項.md` に書く |
| 片づいた、不要になった | カードを消す。消してよいのは、利用者が答えた・決めた・不要と言ったときだけ。聞いていない論点が残っているカードは消さない。履歴は git に残る |
| 利用者が「3 番を進めたい」と言った | その番号のカードを読み、指している確認事項や課題を開いて、作業を始める。利用者に質問するときは、出典の原文と文脈を先に見せる(件名を読み上げて聞かない)。終わったら、カードを消すか移す |
| 作業の区切り | `TODO.md` の「現在地」と一緒に、カードが実際と合っているかを見直す |

- Claude が進める作業は、カードにしない。`TODO.md` に書く
- そのプロジェクトのカードの一覧は、セッションの最初に hook から届く。届いた一覧を見て、返事が来た・片づいた、に気づいたら書き換える
- `タスクボード.md` を初めて作ったら、プロジェクトの `CLAUDE.md` の「参照先」に 1 行足す

## ボードへの反映

- ボードは hook が作り直す。セッションは、スクリプト(`board.py`)を自分で実行しない。ボードのファイルも読まない(作業フォルダの外にあり、ほかのプロジェクトの内容が入っているため)
- `タスクボード.md` を書き換えると、hook から「タスクボードを作り直しました」と知らせが届く。利用者に「ボードに載りました」と伝えるのは、この知らせを受け取ってからにする
- 知らせが届かなかったときは、「`タスクボード.md` には書いた。ボードへの反映は確かめられていない」と伝え、利用者に `/00-board` の実行を頼む
